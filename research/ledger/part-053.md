## K04202
Source `D0727`, original line3, SHA256 `9db2b0d044ffee6fe42febb876e78db33d47cbf0ec58155dd672b9383722ace9`. Status: historical/unadjudicated narrative; English source prose.

**1. Exact station scheduling**
The station schedules slots by iterating a slot index `idx = (idx + 1) % 5` using the dispatcher. `idx <= 2` is the normal tracker path (slots 0, 1, 2) which serves trackers 0-2 respectively, while `idx` 3 and 4 serve a separate path. This makes 5 slots per cycle.
The `idx` is updated at `00e416: strb r3, [r6]` (where `r6` is `0x20004d85`). This happens on dispatcher event 0x144. 
There is a 16MHz timer, TIMER4 (`0x4001a000`), whose CC1 (`0x544`) is read to populate the phase sync value for command 10. The slot length is 15128 ticks (at 16MHz), which is exactly 945.5 us. Since there are 5 slots, the per-tracker poll period is 5 * 945.5 us = 4727.5 us.

## K04204

**3. Missed reply handling**
The station's slot index advances unconditionally (`idx = (idx + 1) % 5`). It does not stall or retry in the same slot. It relies on the tracker waking up on its own schedule (tracker TX after 18910 µs if missed). When a tracker's reply is missed, the station will send command 11 (`0x0B`) with length `1` to report the last IMU frame number successfully received.

## K04205
Source `D0727`, original line14, SHA256 `9db2b0d044ffee6fe42febb876e78db33d47cbf0ec58155dd672b9383722ace9`. Status: historical/unadjudicated narrative; English source prose.

**4. Command 10 (Phase Sync) and Command 14 (Light Sync) construction**
- **Command 10 (Phase Sync):** Built at `016084`. The payload contains the raw `TIMER4 CC1` snapshot (the exact tick when the event fired, loaded from `0x4001a000, #0x544` at `00ac8c`). There is NO offset added to the timer value. It is built ON DEMAND, triggered conditionally when flags at offset `+5` and `+6` of the tracker state struct (`0x20004948` base) are non-zero (checked at `00ac76` and `00ac7a`).
- **Command 14 (Light Sync):** Built at `01658c` (via wrapper at `00e9b8`). It has a 3-byte payload `[01, N, reason]`. `N` is dynamically calculated by counting the number of active trackers (looping and checking offset `0x120` relative to the tracker struct base array at `0x20004948`). `reason` is copied from offset `0x1a9` of the tracker struct (`00ea20: ldrb.w r3, [r5, #0x1a9]`). It is triggered conditionally based on a state variable (`[0x20000066] == 0` checked at `00ea46` and `00ea54`).

## K04206
Source `D0727`, original line18, SHA256 `9db2b0d044ffee6fe42febb876e78db33d47cbf0ec58155dd672b9383722ace9`. Status: historical/unadjudicated narrative; English source prose.

**5. Station TX moment inside a slot relative to the expected window**
Yes, the station explicitly delays its TX moment. It uses `TIMER0 CC0` linked to `RADIO TASKS_TXEN` (`0x40001000`) via PPI Channel 0. The PPI configuration happens at `0148aa` to `0148b8` (`CH[0].EEP = TIMER4 EVENTS_COMPARE[0]` wait, no, `CH[0].EEP = TIMER0 EVENTS_COMPARE[0]` at `0x40008140`).
The exact delay is calculated (near `014896`) by rounding a base time `r1` to the next multiple of `625` (`0x271`). The loop does: `while (r1 > r2) { r2 = r3; r3 += 625; }`. This enforces that the transmission always fires aligned to a strict 625-tick grid, strongly suggesting synchronization with the 625 µs BLE slot boundary to avoid collisions with controller coexistence windows.
