## K03867
Source `D0526`, original line3, SHA256 `b9dd10070730bcae1ab61f1fd078a8a9b67ad57bb117d4d08d8cebf35985809d`. Status: historical/unadjudicated narrative; English source prose.

**What the delta does.** With `transition_guard_grace_s` unset or 0, S1 still arms strict (2 controllers, 150 ms) and `check(require_now=True)` before entering S2. With grace set, that value must be 0..12 and the staged config must be exactly readiness 2 s and phase sample 8 s. S2 then records `grace_until` and leaves the guard in await. Strict is armed only after the dense switch has held continuous replies for 3 s, and only if `check(require_now=True)` succeeds. Command 19 is queued after that check. If `grace_until` is reached first, the step sets strict, records `guard_grace_expired`, and aborts before command 19.

## K03868
Source `D0526`, original line5, SHA256 `b9dd10070730bcae1ab61f1fd078a8a9b67ad57bb117d4d08d8cebf35985809d`. Status: historical/unadjudicated narrative; English source prose.

**Wall clock.** Grace and the S2 stage clock start on the same S1→S2 sample. Fixed costs inside the 12 s are the 8 s phase sample plus the 3 s dense hold, so command 16’s ack and three later RX advances must finish with the arming sample still strictly before `grace_until`. The expiry check is at the top of `step`, before the S3 body, so a sample that is both “hold complete” and `stamp >= grace_until` aborts. At the S1 reply spacing from run3 (about 22 replies/s), ack plus three replies is a few hundred milliseconds, which leaves well under 1 s of slack after the 11 s fixed cost. A command 16 that is still inside the peer engine’s 3 s pending timeout, or a dense hold restarted by a ≥1 s reply gap, is aborted by this cap even though those waits are otherwise legal. That is the hard budget, not a path around it.

## K03869
Source `D0526`, original line7, SHA256 `b9dd10070730bcae1ab61f1fd078a8a9b67ad57bb117d4d08d8cebf35985809d`. Status: historical/unadjudicated narrative; English source prose.

**S4.** The only `transition('S4')` is after the grace rearm block. On the grace path that block runs `set_mode('strict')`, then `check(require_now=True)`, and only then sets `strict_armed`, queues `(19, b'\x00')`, and enters S4. A failed rearm aborts in that `except` and does not queue command 19. Grace expiry also aborts without queuing it and does not set `strict_armed`. The default path has already been strict since S2. Command 16 and the dense 3000 µs phase-lock write still happen under await; that is the authorized window before command 19.
