## K04302
Source `D0752`, original line44, SHA256 `697f1481026cb3eab5b2d5f92401f6fc4862df8eb252e8f439dcd17ab573ae33`. Status: historical/unadjudicated narrative; English source prose.

1. Signal 0 (START) clears `reply.action` to 0 (line 71), counts a slot, sets `phase=2`, and takes the granted length from `request.b` when type is NORMAL (lines 72–85). For this config that length is 900 µs.
2. Still inside START, before any TX wait, it programs TIMER0 CC0 to `D(1892)` and enables COMPARE0 (line 87). `station_v4_runtime.py` line 98 sets `D(1892)` to `slot_us - slot_end_margin_us`. Config is slot 900, margin 100, so CC0 is armed at **800 µs** while START is still on the stack.
3. START then writes the radio and busy-waits for `EVENTS_END` (`RADIO+0x10c`) up to **20000** iterations (line 163), then up to 1024 iterations on `RADIO.STATE` (line 164).
4. Only after that does it sample CC1 (`TASKS_CAPTURE[1]` at `TIMER+0x44`, read `CC[1]` at `+0x544`) and either re-arm CC0 to `now+100` or jump to `slot_end` if `now >= 800` (lines 167–171).
5. Signal 1 is the COMPARE0 poll. At `tick >= 800` it takes `slot_end` (lines 174–193): `stop_radio()`, `phase=1`, NORMAL request `type=1`, `a=interval_us+D(1880)`, `b=D(1876)`. The loader writes `D(1876)=slot_us` (line 612) and `D(1880)=0` when BLE phase lock is off, so the return is distance **4727**, length **900**, `action=3` (`REQUEST_AND_END`). The fault RAM is exactly that struct. `action` stays 3 until the next callback entry clears it, so a leftover 3 after a normal slot end is expected and is not itself the assert.
